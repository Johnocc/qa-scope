# qa-scope

> 보험 콜센터 상담 텍스트를 AI로 **전수 자동채점**하는 QA 시스템 — 전체 커버리지 · 위험 건 탐지 · 상담사 코칭 리포트.

---

## 📌 프로젝트 소개

**2026 아산 AX 글로벌 인재양성 사업**(주관: (사)블루문드림)의 기업과제로 출발한 프로젝트입니다.
과제 제공 기업은 LG CNS이며, 실제 기업 이슈 6건 중 보험 콜센터 상담 품질 평가 과제를 맡았습니다.

실제 상담 데이터는 보안상 제공받을 수 없어, **가상 보험사 '한빛생명'**을 가정한 더미 데이터로 구현하고 검증했습니다.

---

## 🔥 어떤 문제를 푸나

**1. 커버리지 — 대부분의 상담이 평가 없이 묻힌다**
상담사는 1,000~2,000명인데 평가자는 5명. 정기적으로 일부만 샘플링해 손으로 채점하다 보니, 못 본 상담에 문제가 있어도 민원으로 터지기 전까지 아무도 모릅니다.

**2. 일관성 — 같은 품질인데 점수가 갈린다**
평가 기준이 명문화돼 있지 않아 평가자 5명이 각자 판단합니다. 상담사 천 명이 동일한 품질을 내야 하는데, 튀는 값을 잡아낼 일관된 잣대가 없습니다.

---

## 💡 해결 방식

상담 텍스트 **전량**을 명문화된 일관 기준으로 자동 채점하고 —
**한눈에 보고 → 낮은 점수의 원인을 분석하고 → 상담사 피드백으로 연결**하는 하나의 흐름으로 묶어줍니다.

---

## ✨ 핵심 기능

### ① 근거 기반 전수 자동 채점 + 3중 검증
LLM이 상담 텍스트 전량을 **18개 항목·100점** 체계로 채점하고, 항목마다 근거 발화를 인용합니다.
채점 결과는 세 단계로 검증합니다.

1. **형식 검사** (코드) — 출력 JSON 스키마 준수 여부, 위반 시 재시도
2. **인용 원문 대조** (코드) — AI가 인용한 발화가 실제 원문에 존재하는지 확인
3. **2차 AI 확인** (LLM) — 판정의 타당성 재검토

### ② 채점 결과 목록 + 위험 건 표시
저점수·불완전판매 의심 건을 빨간불로 표시하고, 위험도와 점수 순으로 정렬해 담당자가 먼저 볼 것부터 검수합니다. 위험 플래그 6종을 자동 감지합니다.

### ③ 사람 검수 (ver1 / ver2)
AI 채점 결과(ver1)는 원본 그대로 보존하고, 검수자의 수정은 별도 버전(ver2)으로 쌓입니다.
**AI가 전부 채점하되 확정은 사람이 하는 구조**이며, 축적된 AI판–사람판 쌍은 향후 개선 자산이 됩니다.
근거 발화 클릭 시 해당 음성 지점으로 이동합니다.

### ④ 상담사별 대시보드 + 개인 평가 리포트
상담사별 평균 점수·건수·약점 항목을 묶어 코칭 근거로 제공합니다. 개인 리포트에는 **5영역 스파이더(방사형) 차트**, 항목별 상세 점수, 개선 필요 항목, **PDF 다운로드**가 포함됩니다.

### ⑤ 상담 업로드 (녹취시스템 유입 시뮬레이터)
상담 건이 유입되면 즉시 자동 채점이 실행됩니다. 실제 콜센터의 녹취 시스템 연동을 가정한 흐름입니다.

## 📊 평가 루브릭 (5영역 · 18항목 · 100점) — v1.5

| 영역 | 항목 수 | 배점 | 핵심 |
|---|---|---|---|
| A. 상담 도입 | 3 | 12 | 인사·소속고지·본인확인·니즈 파악 |
| B. 업무처리 | 4 | 26 | 정보 정확성·쉬운 설명·적극적 해결 |
| C. 태도·공감 | 3 | 18 | 공감·친절·감정 대응 |
| **D. 보험특화 (불완전판매 방지)** | 6 | **30** | 설명의무·적합성·고지·부당권유 금지 |
| E. 상담 마무리 | 2 | 14 | 재확인·종료 안내 |

> **D영역이 최대 비중(30점).** 보험업에서 불완전판매는 법적 리스크와 직결되므로 의도적으로 가중했습니다. (금융소비자보호법 6대 판매원칙 기반)

**N/A 처리**: 상담 유형에 따라 적용되지 않는 항목은 N/A로 두고, 분모에서 제외해 환산합니다.
(환산총점 = 원점수합 ÷ 적용배점합 × 100)

## 🏗 설계 원칙

**판단은 LLM이, 계산은 코드가**
원문 해석과 항목 판정은 LLM(temperature 0)이, 배점 산출·N/A 재분배·위험 플래그 확정은 전부 코드가 담당합니다. 같은 입력이면 같은 점수가 나오도록 강제하기 위해서입니다.

**기준은 코드 밖에**
루브릭·니즈-상품 매칭표·N/A 규칙은 전부 문서로 관리합니다. 기준이 바뀌면 문서를 교체하지 코드를 고치지 않습니다. 저점수 컷 등 정책값은 관리자 설정으로 분리했습니다.

**문서 성격에 따라 공급 방식을 나눈다**
작고 전부 필요한 문서(루브릭·매칭표)는 프롬프트에 통째로 삽입하고, 크고 일부만 필요한 문서(약관)만 RAG로 검색해 공급합니다. RAG를 붙이는 목적은 정확도가 아니라 **약관 교체 시나리오에 대한 확장성**입니다.

**어댑터 분리**
입력·참조자료·LLM·저장 4개 지점을 어댑터로 감싸, 특정 API나 인프라에 묶이지 않도록 설계했습니다. 금융권의 온프레미스 전환 요구에 대응하기 위한 구조입니다.

## 🛠 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 프론트엔드 + API | Next.js (App Router) · TypeScript |
| LLM | Google Gemini (`gemini-2.5-flash`) |
| 벡터 DB (약관 RAG) | Chroma Cloud · `gemini-embedding-001` |
| 데이터베이스 | MySQL (Aiven) |

> 채점 엔진은 별도 서버 없이 Next.js API 라우트에 두었습니다.
> LLM·저장소·검색·입력은 어댑터로 분리해 교체 가능합니다.

## 🎯 성공 기준과 결과

**정확도** — 목표: 사람이 직접 채점한 정답지(골든셋)와 항목 일치율 80% 이상
→ **달성: 86.5~89.7%** (골든셋 7건 · 126개 항목 판정 기준)

**사용성(UX)** — 녹취를 하나씩 열어보지 않고, 위험 건 발견 → 원인 확인 → 피드백 근거 찾기까지 한 화면 흐름 안에서 완료
→ 달성 (화면 ①→②→③→④ 연결)

### 검증 방법

1. **골든셋 구축** — 상담 7건(126개 항목 판정)을 3인이 독립 채점 후 합의로 확정
2. **동결** — AI 채점 시작 전 골든셋·더미·매칭표를 동결. 결과를 본 뒤의 기준 수정 금지
3. **노이즈 밴드 측정** — 동일 조건 반복 실행으로 자연 변동폭(±1.6%p)을 먼저 측정
4. **구성 실험** — 문서 공급 방식을 바꿔가며 대조 실험, 사전 기준을 통과한 구성만 채택

> 채택하지 않은 실험도 기록으로 남겼습니다. 상품설명서 코드 조회 전환 실험은 일치율 -2.4%p로
> 사전 기준(노이즈 밴드)을 벗어나 보류했습니다.
