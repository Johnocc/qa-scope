- 지금은 배포 URL만 알면 누구나 4개 화면과 API를 열 수 있다. 로그인은 그 앞에

  시드 계정 1개가 그 "발급된 계정" 역할을 한다.

## 2. 아키텍처 개요

```
[브라우저] → 미들웨어(middleware.ts): 세션 없으면 /login으로 리다이렉트
           → /login: 로그인 화면 (민재 or John+CC)
           → POST (NextAuth Credentials): users 테이블 대조 (bcrypt.compare)
           → 성공: JWT 세션 쿠키 발급 (HttpOnly·Secure) → 원래 가려던 화면으로
```

- **HttpOnly 쿠키**: 자바스크립트가 쿠키를 못 읽게 하는 속성 → XSS(스크립트 주입 공격)로
  세션을 훔치는 걸 방지.
- **Secure**: HTTPS에서만 쿠키 전송. Vercel은 기본 HTTPS라 자동 충족.
- **JWT 세션**: 로그인 상태를 서버 DB가 아니라 서명된 토큰(쿠키)에 담는 방식.
  서버가 서명을 검증하므로 위조 불가. DB 테이블이 안 늘어나는 게 장점.

  (회원가입·비밀번호 찾기 링크 **없음** — 관리자 발급 구조라 존재 자체가 모순).

  (어느 쪽이 틀렸는지 알려주지 않음 — 계정 존재 여부 노출 방지, 보안 관례).

### 확정 B — 로그인 시도 제한 포함 (John 확정, 2026-07-16)

- **방식: 시간창 제한(rate limit).** 같은 계정 연속 5회 실패 → 5분간 시도 거부 → 자동 해제.
- **계정 잠금(lock) 방식은 채택 안 함** — 잠기면 관리자 해제가 필요해 시연 중 복구 불가.
  시간창 방식은 무차별 대입을 막으면서(초당 시도 불가) 사람 실수는 5분 후 자동 복구.
- 저장: 서버 메모리(Map) — DB 테이블 불필요. 데모 규모에 충분, 서버 재시작 시 초기화.
- 실패 응답 문구: 제한 발동 시 "잠시 후 다시 시도해 주세요" (남은 시간 미표기 — 공격자에게 정보 최소화).
- 확장 슬라이드에는 이 항목 대신 2FA·감사 로그·계정 잠금 정책만 남긴다.
