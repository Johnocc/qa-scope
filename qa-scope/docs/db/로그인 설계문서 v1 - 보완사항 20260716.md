## 추가 확정 요소

	•	[A 확정] 미들웨어 예외 없음: /login, /api/auth/*, 정적 자산만 열고 /api/* 전체(health 포함) 401 잠금. 채점 스크립트는 API를 안 거치는 구조라(함수 직접 import) 영향 없음을 실사로 확인했습니다
	•	[C 확정] NEXTAUTH_SECRET: 제가 생성해서 Vercel 환경변수 + 제 로컬 .env에 넣겠습니다. 우현님은 Vercel 대시보드에서 확인해 로컬 .env에 옮겨 쓰시면 됩니다. 코드·.env.example·디스코드에 값 기재 금지 (.env.example엔 변수명만). NEXTAUTH_URL도 같이 등록해두겠습니다
	•	[D 확정] 시드 비밀번호: 시드 스크립트는 SEED_ADMIN_PASSWORD 환경변수에서 읽어 bcrypt 해시 후 저장. 변수 없으면 에러로 중단 — 기본값 폴백 금지. 이 변수는 Vercel에는 넣지 않습니다(시드 실행 시에만 필요)
	•	스키마: users 테이블은 scripts/schema.sql에 반영 (팀 규칙 npm run db:schema 유지)
  •	users 테이블 (§3): id(PK) / username(varchar, unique) / password_hash / display_name / created_at. 시드는 qa_manager 1건만 — 회원가입 기능은 만들지 않습니다
	•	로그인 실패 문구 (§5): 아이디가 틀렸든 비밀번호가 틀렸든 “아이디 또는 비밀번호가 올바르지 않습니다” 단일 문구로 통일합니다. 어느 쪽이 틀렸는지 구분해서 알려주면 계정 존재 여부가 노출되므로 금지입니다
	•	시도 제한 발동 문구: “잠시 후 다시 시도해 주세요” — 남은 시간은 표기하지 않습니다

추가 규칙 2건:

	1.	next-auth 버전은 설치 전에 공유 부탁드립니다. v4와 v5(Auth.js)는 설정 방식이 크게 달라서, 어느 버전 기준으로 갈지 먼저 맞추고 시작해야 중간에 갈아엎는 일이 없습니다. 조사해보시고 제안 주시면 확정하겠습니다.
	2.	feat/auth는 통합 검증 전까지 develop에 병합하지 않습니다. 인증은 전 화면을 통과하는 층이라, 검증(비로그인 차단 / 로그인 정상 / 로그아웃 / 만료) 통과 후 병합합니다.

스코프 제외: 검수자 이름 자동 기입 연계는 이번 작업에 포함하지 않습니다 (ReviewPanel 수정이 딸려오는 별도 건으로 분리 확정). users 테이블~시도 제한까지만 진행해 주세요.
